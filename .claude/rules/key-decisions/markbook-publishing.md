### KD #129

Report-card comment hard-gate at publish + cumulative FCA render (Sprint 57, 2026-06-06; assumptions register E1). HFSE confirmed: report cards must be complete on comments before publishing, and only **submitted** comments show to parents. **(1) Hard gate:** publishing a `(section, term)` window (KD #10) is **hard-blocked** server-side (`POST /api/report-card-publications` → 422 `comments_incomplete`) until every term the card will display (terms **1..N**, T1–T3 only) has a **submitted + non-empty** FCA write-up for each student **required for that term**. Only the comment check is hard; all other publish-readiness checks stay **soft** "publish anyway" (KD #28/#75, M3 — v1). T4 is exempt (no FCA comment, KD #49). **(2) Cumulative render:** `ReportCardDocument` renders comment boxes for terms **1..viewingTermNumber** (T1→1 box, T2→T1+T2, T3→all three; T4→none), each with **its own** term's virtue-theme heading (KD #49); a term with no submitted comment is omitted (no empty box) — the gate guarantees published cards have them. **(3) Roster-correct per term** (KD #120): a student is required to have a term-T comment only if active (`!= withdrawn`, by `student_id`) AND enrolled by term T (`enrollment_date == null || <= term.end_date`) — a late enrollee who joined in T2 is NOT required to have a T1 comment (else the cumulative gate false-blocks; HFSE has many late enrollees, R1). **Shared helper `lib/markbook/comment-completeness.ts`** (`missingCommentStudents` / `commentCompletenessForTerm` / `cumulativeCommentGaps` / `rosterRequiredForTerm`, unit-tested) feeds BOTH the publish enforcement AND the `publish-readiness` advisory row, so checklist display and server block cannot drift. UI (`publish-window-panel.tsx`): the comment row is a destructive "Required to publish" hard-block (disabled "Comments required", not "publish anyway") deep-linking to Evaluation; other rows stay soft. No migration.

### KD #138

Virtue theme folded into the report-card comment hard-gate + bulk-publish readiness checklist (Sprint 59, 2026-06-08). Two publish-flow gaps surfaced by an in-session review. **(1) Virtue → hard gate.** The FCA comment is the one hard publish gate (KD #129); the term's **virtue theme is the _heading_ of that comment block** (KD #49, "…Comments (HFSE Virtues: …)"). Previously `terms.virtue_theme` was only a _soft_ readiness row, so a card could publish with complete comments under a missing virtue heading. Now the shared `cumulativeCommentGaps` (`lib/markbook/comment-completeness.ts` — the single source for both the checklist display AND the server block) gaps a displayed term (1..N, T1–T3) when comments are missing **OR** `virtue_theme` is null/blank: `CumulativeTerm` gained `virtue_theme?`, `CumulativeGap` gained `virtueMissing`. Both callers pass the column — `POST /api/report-card-publications` (422 `comments_incomplete`, message + `comment_gate.gaps[].virtue_missing`) and the `publish-readiness` route (which **dropped its standalone soft `virtue_readiness` block** — the hard gate subsumes it). The publish-window-panel's hard comment row now lists virtue gaps + deep-links to `/evaluation/virtue-themes`. **Virtue is the ONLY check elevated to hard** — it's coupled to the already-hard comment, HFSE designed the comment to be virtue-framed, and it's safe (one value per term, no per-student/false-positive risk). Grading-locked/attendance/T4/letterhead stay **soft** (KD #28 — false-positive/operator-lockout risk). **Operational note:** after this, publishing T1–T3 requires a virtue theme set for every displayed term (registrar sets them at `/evaluation/virtue-themes`, KD #137). **(2) Bulk-publish readiness checklist.** `bulk-publish-dialog.tsx` previously looped the gated POST but showed no readiness + halted on first failure. It now fetches `publish-readiness` per section on open/term-change (chunked 5, cached by `${id}:${termId}`), classifies each **✓ ready / ⚠ warn (soft: unlocked sheets, attendance gaps, T4) / ✗ blocked (`comment_gate.ok===false` — comments or virtue)**, disables+unchecks blocked rows, and **publishes all ready+warn, skips blocked**, with a summary toast (published/skipped/failed) — soft never blocks bulk (consistent with single-section "publish anyway"). Spec/plan: `docs/superpowers/{specs,plans}/2026-06-08-publish-gate-virtue-and-bulk-checklist*`. No migration.

### KD #139

Publish-anyway **override tracking** + empty-card **hard blocks** (Sprint 59, 2026-06-09; migration 073). Amends KD #28/#129/#138 (does not reverse them). The registrar's framing: report cards are serious, but incomplete data is **often legitimate** (esp. late enrollees — earlier terms are genuinely blank), so the model is **warn → allow → record the override**, not hard-block everything. (An all-hard-gate + superadmin-break-glass design was explored and **rejected** in favour of this.) **(1) Shared evaluator** `lib/markbook/publish-readiness.ts::computePublishReadiness(service, sectionId, termId)` — the entire computation formerly inline in the `publish-readiness` GET route was moved here (single source of truth, like `cumulativeCommentGaps`); the GET route is now a thin wrapper. It returns the same detail shapes **plus** a verdict: **`hardBlockers`** (`comments_incomplete` [interim only — `comment_gate.ok===false`, includes virtue per KD #138; T4 exempt per KD #49], **`no_students`** [empty active roster], **`no_grading_sheets`** [interim: term has no sheets; T4: zero across the 4 terms]), **`softGaps`** (`sheets_unlocked`, `attendance_incomplete`, + T4 `grades_missing`/`nonexam_finals_missing`/`letterhead_incomplete`), and `canPublish = hardBlockers.length===0`. **(2) Empty-card hard blocks (bug fix):** previously a section with **no students** or **no grading sheets** passed every check _vacuously_ (0 missing of everything → green → published an empty window). These are now hard blockers ("no card," not "incomplete data"). **(3) Override tracking:** `POST /api/report-card-publications` calls the evaluator; any hard blocker → **422 `{ code:'publish_blocked', hardBlockers }`** (replaces the comment-only `comments_incomplete` block — that code is now one hard blocker among the three). A clean publish writes `published_with_gaps = null`; a "publish anyway" past soft gaps writes a snapshot **`published_with_gaps = { gaps, by, at }`** (migration 073 — nullable `jsonb` on `report_card_publications`; **null = clean**) + audit context `overridden:true` + `gaps` (codes). The override is **accountability only — NOT shown to parents**; the publish-window-panel surfaces a "Published with gaps: …" note on such a window (the GET list select now includes the column). **(4) Soft model unchanged:** grades/attendance/sheets-locked/letterhead stay overridable ("Publish anyway"); comments+virtue stay hard. **No superadmin break-glass** (only needed for an all-hard gate, which we didn't build). Soft-check scope is **current-term**; comments stay **cumulative** (1..min(N,3)). Bulk dialog `classify()` keys off `hardBlockers`/`softGaps` (blocked includes the new existence blockers); the 422 skip-detection moved to `code:'publish_blocked'`. The panel falls back to the legacy `comment_gate.ok` check if the verdict arrays are absent (safety). New test `__tests__/markbook/publish-readiness.test.ts`. Migration 073 user-applied.

### KD #145

Bulk-publish dialog — concern-aware fix links (expandable rows; 2026-06-11). The bulk report-card publish dialog (`components/admin/bulk-publish-dialog.tsx`) showed each section's readiness as a pill + **one generic link → always `/markbook/grading`**, regardless of the actual gap. Now each section row expands (a new **`SectionReadinessRow`**, `aria-expanded` chevron disclosure) to a mini checklist of its **specific** concerns, each deep-linking to its fix surface carrying the selected term — mirroring the single-section `publish-window-panel` `ChecklistRow` (KD #75), condensed. A pure, unit-tested **`components/admin/bulk-publish-concerns.ts`** (`concernsFor` + `concernHref`) derives concerns from the verdict codes already fetched (`hardBlockers`/`softGaps`, KD #139): `comments_incomplete` is **split** into `comments` (→ `/evaluation/sections/{id}?term_id=`) and `virtue` (→ `/evaluation/virtue-themes`) via `comment_gate.gaps` (KD #137); `attendance_incomplete` → `/attendance/{id}?term_id=`; `no_grading_sheets`/`sheets_unlocked`/`grades_missing` → `/markbook/grading?grading.section={name}` (facet, KD #84); `nonexam_finals_missing` → `/markbook/report-cards`; `letterhead_incomplete` → `/sis/admin/school-config`; `no_students` → label-only (no quick fix). Hard concerns use a destructive icon, soft use amber (icon **+** label, never colour-only). Links open in a new tab (dialog stays open); blocked sections stay expandable (checkbox disabled) so the registrar can reach the fixes. UI-only — `classify()` verdict, the publish POST, and the readiness route are unchanged. No migration. Spec/plan: `docs/superpowers/{specs,plans}/2026-06-11-bulk-publish-concern-links*`.

### KD #148

Report-card **N.A. for terms a student wasn't enrolled in** — enrolment-coverage proration (2026-06-15; no migration). A student not enrolled for a full term used to render misleading data: **attendance** showed `0 present / full-term-days` (reads as "absent all term" and deflated the cumulative %), because `build-report-card.ts` overrode each term's `school_days` with the full calendar count while `days_present` came from the prorated rollup; and **grades** left a hole — `computeAnnualGrade` prorates `null`+`is_na` terms but a pre-join term with **no entry at all** (sheet predated the student) was blank/`is_na=false`, so annual/GA returned `null` (incomplete) instead of prorating. **Rule (single source of truth):** a student's **enrolment coverage** = union of `[enrollment_date, withdrawal_date]` intervals across their `section_students` rows for the AY (a transfer contributes two abutting rows → continuous; active row open-ended; null `enrollment_date` = from year start). Per term, **enrolled-school-days** = teaching days in `[term.start, term.end]` ∩ coverage; the term is **N.A. when that count is 0**. Dates are date-only SGT compared as `yyyy-mm-dd` strings (KD #32), inclusive end-boundary. **New pure helper `lib/report-card/enrolment-coverage.ts`** (`isEnrolledForTerm` / `dateInCoverage` / `termEnrolment`, unit-tested); `build-report-card.ts` threads enrolment + term dates, marks non-enrolled terms N.A. (attendance excluded from the denominator + cumulative %, grade cells N.A.) and prorates annual/GA over only the enrolled terms. Extends KD #113 (attendance proration) + KD #117 (`enrollment_date` as joining-term truth). Spec/plan: `docs/superpowers/{specs,plans}/2026-06-15-report-card-na-non-enrolled-terms*`.
