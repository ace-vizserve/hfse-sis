## Attendance — daily writer + school calendar

### KD #47

Attendance is sole writer of daily attendance. Markbook/Records/Parent are read-only consumers. Audit prefix `attendance.*`. `16-attendance-module.md`.

### KD #50

School calendar has five day-types (`school_day`, `public_holiday`, `school_holiday`, `hbl`, `no_class`) per `school_calendar.day_type` (migration 019). `school_day` + `hbl` are encodable (attendance grid accepts writes). The other three reject writes (409 on `/api/attendance/daily`). `is_holiday` is legacy, derived via BEFORE trigger from `day_type`. "Important dates / special events" stay on `calendar_events` as an overlay layer, not a day-type. **Audience precedence rule** (migration 037): both tables carry `audience IN ('all','primary','secondary')`; on read, an audience-specific row overrides the matching `'all'` row for the same date when the section's level type matches. Attendance writer at `app/api/attendance/daily/route.ts` resolves the section's level via `lib/sis/levels.ts::levelTypeForAudienceLookup`; preschool sections (YS-L/J/S) fall back to `audience='all'`. Unique key on `school_calendar` widened to `(term_id, audience, date)` so primary + secondary can each hold a row for the same date. `getEncodableDatesForTerm` + `isHoliday` apply the same precedence.

### KD #55

`/attendance` route split. `/attendance` is the analytics dashboard (registrar+ only); `/attendance/sections` is the section picker (teachers land here); `/attendance/[sectionId]` remains the daily writer. Teachers visiting `/attendance` redirect to `/attendance/sections`. Sidebar isActive: exact-match `/attendance`, prefix-match `/attendance/sections`.

### KD #76

Calendar audience scope + typed event categories (migration 037). `school_calendar` and `calendar_events` both carry `audience IN ('all','primary','secondary')`; `calendar_events` also carries `category IN (term_exam | term_break | start_of_term | parents_dialogue | subject_week | school_event | pfe | ptc | other)` + `tentative bool`. KD #50's 5 day-types stay the attendance gate — new event types live on the overlay layer, NOT as new day-types (a term-exam day is still a school day with attendance taken). UI at `/sis/calendar` exposes an `?audience=all|primary|secondary` filter tab; cell click-cycle and event create write to the active filter. Audience precedence rule: an audience-specific row beats the matching `'all'` row for the same date (KD #50 documents the read-side rule). Carry-forward stays manual: `components/attendance/copy-from-prior-ay-dialog.tsx` (renamed from copy-holidays-dialog) handles both day-type overrides + events with year-shift; default `markTentative=true` flips every copied row to `tentative=true` so the registrar reviews each before locking. Preschool (YS-L/J/S) deferred — preschool sections always read `audience='all'`; future scope can extend the enum with one CHECK update + dropdown additions.

### KD #94

Vacation-leave subtype + per-term quotas + configurable defaults (migration 048). Verified against HFSE's T1 attendance workbook: the registrar's spreadsheet header carries two policy labels ("4 Vacation Leaves: 1 per term" + "5 days (per year) Urgent/Compassionate Leave"), but only one subtype existed in the schema (`ex_reason ∈ mc | compassionate | school_activity`); vacation was recorded as a free-text Excel cell comment ("1 VL approved", "took vacation leave for outing"). Now structured: **`attendance_daily.ex_reason` check widened** to include `'vacation'`; **`students.vacation_leave_allowance_per_term smallint`** added as a nullable per-student override (NULL = use school default — deliberately cleaner than `urgent_compassionate_allowance`'s `NOT NULL DEFAULT 5`, which is left as-is to avoid a breaking change); **`school_config` gains `default_compassionate_allowance_per_year smallint default 5`** + **`default_vl_allowance_per_term smallint default 1`** — these become the canonical school-wide defaults the new `<VacationAllowanceInline>` reads when a student row is NULL. Partial index `attendance_daily_vacation_idx (section_student_id, term_id) where ex_reason='vacation'` for per-term quota counters. **Read path**: `getVacationLeaveUsage` / `getVacationLeaveUsageForSection` in `lib/attendance/queries.ts` mirror the compassionate helpers but scope on `term_id` (no AY-wide carry-forward). **Drill**: new `'vacation-leave-quota'` target on `AttendanceDrillTarget`, `'vacation-leave'` row-kind, `VacationLeaveUsageRow` row shape, `rollupVacationLeave` rollup. `lib/attendance/drill.ts` stays client-bundle-safe by accepting `defaultVlAllowance` as a parameter (caller fetches from `school_config` and passes in) instead of importing the server-only school-config module at top-level — important: when a server-only module reaches a client component via a value import in any transitively-imported file, Next 16 errors with `'server-only' cannot be imported from a Client Component module`. Drill API route forwards `?termId=` so per-term filter ships server-side. **UI**: wide-grid gains `EX:vacation` as the 4th EX subtype (letter mnemonic `EV` derives via existing `slice(3,4)` logic — no extra branch); soft warning toast fires from `writeCell` when a 2nd-VL-in-term would exceed `vlAllowance` (write still proceeds — registrar can grant exception). New `<VacationLeaveQuotaCard>` on the attendance dashboard with `Umbrella` icon + `brand-sky → brand-indigo` gradient distinguishes it from the compassionate card. Per-student `/attendance/students/[studentNumber]` page mounts both cards in a `md:grid-cols-2`. New `<VacationAllowanceInline>` mirrors `<CompassionateAllowanceInline>` but treats NULL as the canonical "use school default" state — Reset writes NULL back so future school-default changes propagate. New `PATCH /api/sis/students/[enroleeNumber]/vl-allowance` route + `'sis.vl_allowance.update'` audit action. SIS Admin school-config form gains an "Attendance quotas" section group; the route's `requireRole` widens from `['superadmin']` to `['superadmin', 'school_admin']` per KD #39. **Out of scope**: bulk Excel import doesn't yet parse cell comments → VL subtype (future enhancement); priority-panel VL chip deferred (the dashboard card is the primary signal).

**Update (Sprint 57, 2026-06-06) — aligned to HFSE's sheet (migration 070).** Verified against HFSE's actual T1 attendance workbook legend (EX = "Excused (MC-Excuse Leave)"; Vacation + Compassionate are the only quota'd leaves) — there is **no "school activity" excuse**. So `ex_reason` was trimmed to **`mc` (relabeled "MC / Excuse leave") · `compassionate` · `vacation`** and `school_activity` was **removed**: migration **070** remaps existing `school_activity` → `mc`, then tightens `attendance_daily_ex_reason_chk` to those three (NULL-allowed preserved). `EX_REASON_VALUES`/`EX_REASON_LABELS`, the dashboard/drill EX-reason breakdown (donut label ↔ enum reverse-map), and the seeder were all updated to the 3. Cross-ref KD #132 (grid encodes the 4 HFSE statuses P/A/EX/L — cell shows "EX" for any subtype, the 3 nested under an `<optgroup>`, still selectable + stored for the quotas).

### KD #113

Late-enrollee attendance proration (migration 068). `recompute_attendance_rollup(p_term_id, p_section_student_id)` now fetches `section_students.enrollment_date` and filters `attendance_daily` entries to `date >= enrollment_date` before counting school_days / present / absent. For active students (`enrollment_date IS NULL`) behaviour is unchanged. For late enrollees joining in T3, T1 and T2 rollups produce 0/0/0 stats instead of counting any pre-enrollment entries that exist due to backfill. **Wide-grid**: `app/(attendance)/attendance/[sectionId]/page.tsx` now selects `enrollment_date` from `section_students` and passes it through `WideGridEnrolment`; cells whose calendar date is before the student's `enrollment_date` render as non-interactive dimmed spans (`bg-muted/40 opacity-40`) with a "Before enrolment date" tooltip — existing back-dated entries still display dimmed rather than being silently hidden. Extends KD #68 (late-enrollee term detection).

### KD #98

School-holiday HBL overlay (migration 051). `school_calendar.hbl_overlay boolean NOT NULL DEFAULT false` makes a `day_type='school_holiday'` row simultaneously encodable — teachers submit attendance as on a standalone HBL day. `isEncodableDayType` in `lib/schemas/attendance.ts` + the write-gate in `app/api/attendance/daily/route.ts` treat `school_holiday + hbl_overlay=true` as encodable. The `is_holiday` BEFORE trigger is NOT changed — overlaid rows remain `is_holiday=true`. Extends KD #50's model: 5 day-types stay the canonical gate; HBL overlay is a per-row modifier only meaningful when `day_type='school_holiday'`. Matches HFSE's published AY2026 calendar where marking-day and awards-deliberation day carry both "School Holiday" and HBL labels on the same cell.

### KD #116

Attendance Daily view + shared current-term resolver (Sprint 49). The section attendance page (`app/(attendance)/attendance/[sectionId]/page.tsx`) gains a **Term sheet | Daily view** toggle. **Daily view** (`components/attendance/daily-entry.tsx`) is a today-centric "mark-the-exceptions" surface: the whole roster defaults to Present (mint Present button, `aria-pressed`) and the teacher only flips absences / lates / EX; marks re-seed per selected date so changing the date reloads that day's saved state, with saved-state day cards + dedicated per-day stat cards, locked to the current term. New **student attendance lookup** sheet (`components/attendance/student-lookup-sheet.tsx`) searches a student and shows their record without leaving the section. **Shared current-term resolver** (`lib/sis/current-term.ts::resolveCurrentTerm` / `resolveCurrentTermId` — pure, unit-tested): resolves "which term is now" from the date with a layered fallback (1 window containing today → 2 manual `is_current` flag → 3 most-recently-ended term → 4 earliest term), because `terms.is_current` is often left unmaintained and flag-only pickers silently defaulted to T1. Attendance + SIS (`app/api/sis/today-term/route.ts`) refactored onto it. No migration. Extends KD #55. (A global `components/ui/screen-guard.tsx` min-width overlay, mounted in `app/layout.tsx`, also shipped this sprint — attendance grids assume desktop.)

### KD #130

Recompute proration when `enrollment_date` changes (Sprint 57, 2026-06-06; assumptions register A1). Extends KD #113. The late-enrollee proration (`recompute_attendance_rollup` filters `attendance_daily` to `date >= enrollment_date`) was only re-applied on attendance writes — so correcting a wrongly-prorated student's `enrollment_date` left the existing rollups stale until the next write. Now the section-students PATCH (`app/api/sections/[id]/students/[enrolmentId]/route.ts`) fires `recompute_attendance_rollup(term_id, section_student_id)` for **every term in the AY** after a **real** `enrollment_date` change (compared to the prior value — idempotent re-saves don't re-fire), via the service client, **non-fatal** (per-term `console.warn` on error; the edit already committed, never 500s), folded into the existing `enrolment.metadata.update` audit context (`recomputedAttendance` + term count). Not a discretionary override (HFSE rejected that) — proration follows `enrollment_date`, so fixing the date is the correction path; this makes it take effect. The only date-write path today is the late-enrollee transition; the change-guard also catches a future direct date editor automatically. No migration.

### KD #132

Attendance mark colours = HFSE paper-sheet palette (Sprint 57, 2026-06-06; assumptions register A3). HFSE wants the encode/marking grid to match their paper sheet: **P = Light Blue · A = Yellow · EX = Cyan · L = Pink**. Added as design tokens in `app/globals.css` (Hard Rule #7 — raw `--av-*` values live there only; semantic `--color-attendance-{present,absent,excused,late}` + `--color-attendance-mark-ink` for the dark ink) and applied **only** to the marking surfaces — `components/attendance/wide-grid.tsx` (term-grid cells + legend, single-source `STATUS_CELL_WASH`) and `components/attendance/daily-entry.tsx` (the P/L/A/EX segmented control). Present (light blue, ~210°) and Excused (cyan, ~175°) are deliberately distinct in hue + luminance so they don't blur in a dense grid; the letter label always shows (colour is never the only signal — accessibility). **Scoped strictly to the marking grid** — the attendance dashboard, drills, quota cards, day-type/calendar chips, and the Daily-view summary tiles keep the app's semantic mint/amber/destructive palette (§9). A deliberate local colour language for the encode surface only. No migration.

**Encoding collapsed to the 4 HFSE statuses (same sprint).** HFSE encodes attendance as **P / A / EX / L** only — the grid had been displaying the EX subtype mnemonics (EM/EV/EC/ES). The cell now shows the canonical letter (**EX** for any excused subtype) via a `pointer-events-none aria-hidden` overlay `<span>` over the native `<select>` (its own text `text-transparent`) — the dropdown options stay descriptive (EX · MC / Excuse leave · Vacation leave · Urgent / compassionate) so the teacher still **picks** the subtype, and `ex_reason` is still **stored** to drive the VL (1/term) + compassionate (5/yr) quotas (KD #94). Before-enrolment dimmed span + the legend also collapsed to the 4 statuses; the full kind stays on the cell tooltip. Daily view already labelled its EX control plainly. Colours/schema/`writeCell`/quota logic unchanged.

Term-scoped range (`resolveRange` thisTerm cascade, KD #79). `/attendance/compare` redirects to `/attendance/insights`; nav Compare→Insights (`lib/auth/roles.ts`). Seasonal = `BuildingHistoryCard`. No migration.
