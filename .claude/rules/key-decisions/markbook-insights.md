Confirmed the masterfile is correctly modelled as a **computed view over normalized tables** (not a stored flat sheet — `loadMasterfile` reads `students`/`section_students`/`grade_entries`/`subject_configs`/`attendance_records`, awards from `school_config` via `lib/compute/awards.ts`, GA via `annual.ts`); this closes the two real gaps + reframes the on-screen surface. **(1) Teacher's Comments** — `loadMasterfile` batch-loads FCA write-ups (`evaluation_writeups`, T1–T3, resolved by current-roster `student_id` per KD #120, content col `writeup`) onto `commentsByTerm`. **(2) Excel report-book export** — server-only `lib/markbook/masterfile-export.ts` builds the exact workbook layout (identity · per examinable subject T1–T4/Overall/Award · per non-exam subject T1–T4 + **Final** letters · Overall Academic Award · per-term attendance + totals · comments) from the same computed data via `xlsx` (`!merges` group headers); `GET /api/markbook/masterfile/export` (registrar | school*admin | superadmin) mirrors the page's `?ay/level/class` filter, multi-section aware; export is unchanged by the dashboard's refinement filters. **(3) On-screen reframe** — the flat grid is no longer the primary surface; the page (now `/records/academic-summary` per KD #127) is a **tracking dashboard** (`components/markbook/masterfile-dashboard.tsx` + `masterfile-view.tsx`; pure aggregates in `lib/markbook/masterfile-dashboard.ts`, unit-tested): three sections — \_At a glance* (neutral snapshot counts: grades recorded / sheets locked / comments in / attendance logged / full results — **no readiness verdict**, a full count is a quiet positive, nothing flags amber/red), _How they're doing_ (award distribution, GA spread vs bands, subject performance, attendance health — incomplete shows "pending," never faked), _Worth a look_ (Still-coming-in + Standing-out watchlists, deep-linked to the Records student page). A **Dashboard | Table** toggle (`?view=`) keeps the raw grid; Term/Subject/Status filters are client-side over the in-memory payload. **It is a tracking view, not a readiness gate** (registrar's framing). No schema change; `grading_sheets.is_locked` added to the loader select for the lock count. Cross-ref KD #95 (masterfile + awards), KD #120 (roster-safe write-up counts), KD #54/#57 (dashboard framework).
