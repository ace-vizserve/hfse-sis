# HFSE SIS — Claude Instructions

A Student Information System for HFSE International School, Singapore. Modules — Markbook, Attendance, Evaluation, P-Files, Records, Admissions, SIS Admin — are surfaces of one student record, not sibling apps. The module switcher moves between them; `studentNumber` is the backbone.

## Stable rules — auto-loaded (every session)

**Everything inside `.claude/rules/` is read into context automatically, every session.** That is a Claude Code behaviour, not something a file can opt out of — a `load: on-demand` line in a file's frontmatter is descriptive only and does not stop it loading. So only four files live there, deliberately:

@.claude/rules/always-do-first.md
@.claude/rules/hard-rules.md

- `.claude/rules/design-system.md` — binding design pointer; too important to risk missing (it is small, and only points at the full docs).
- `.claude/rules/key-decisions.md` — the KD index, so a "KD #N" cite resolves with no extra read.

Do not edit any of the four without explicit user approval, and **do not add new files to `.claude/rules/`** — anything put there is paid for in every session. On-demand material goes in `docs/` (below).

## Session context

✅ **THE SCHOOL CALENDAR COMES FROM THE SCHOOL'S OWN CALENDAR NOW, NOT FROM ATTENDANCE REGISTERS — APPLIED TO PRODUCTION 2026-09-15, migration 158 applied, code deployed. Full account: KD #214 + #215.** Every AY2026 row had been inferred from finished registers, one ad-hoc importer per term. A register shows THAT a day was blank, never why; has no columns for anything with no attendance footprint; collapses primary and secondary sittings of one exam into one row; and does not exist until the term is over. **T4 opened 14 Sep with 49 rows, every one a plain school day** — 8 published closures were still markable, 5 were the wrong kind of day, 72 events were missing. Applied: 12 closures corrected, 63 events added, 42 given a real level scope. `scripts/audit-calendar-vs-sources.ts` re-runs the whole comparison read-only at any time.

✅ **AN EVENT SAYS WHICH LEVELS IT IS FOR (migration 158).** Mr Ace: _"i have seen events named P6 Fieldtrip and its assigned to whole school which is wrong."_ `calendar_events.levels text[]` + `section_ids uuid[]`, mutually exclusive; `audience` stays and is **derived by trigger** because three readers branch on it. Measured after: a P1 register shows 7 July events and **none is the Leadership Camp**; P6 shows 10, camp 3/3. ⚠ **A multi-day event is not necessarily one row** — the T3 import wrote one row per tagged date, so matching a backfill on `start_date` scoped day 1 and left days 2–3 whole-school **while the count still read right**. ⚠ Closures are deliberately NOT level-scoped: `school_calendar` has no level column and all 28 labelled day rows are whole-school. ✅ **The source conflicts were settled by the sources, not by a judgement call** — Mr Ace: _"i mean the documents cant answer your concern?"_ They could. AY2025's register states _"Leadership Camp P4 - Sec 4"_ outright; the T3 date tags carry `SE` on 13 of 20 sheets for 14–16 Jul and none for the published 8–10 Jul (402 marks those days); 12 May holds 370 marks so Vesak's masthead date is AY2025's; and 5 Jul is a Sunday, so the Youth Day Celebration is the published 3 Jul. **Resolutions are ENCODED in `reconcile.ts::KNOWN_SOURCE_ERRORS` with their evidence**, so a re-run cannot undo them. ⚠ **Ask the documents before asking Mr Ace.** 🔴 **43 closures + 9 events fall outside every term window with nowhere to store them** (New Year, term breaks, the Nov–Dec block); both calendar tables are term-scoped. **Still open.**

🔴 **THE LESSON WORTH KEEPING: A TRIGGER FIRES FOR EVERY WRITER, A ROUTE DOES NOT.** Migration 152 shipped **two data-loss bugs** for this one reason, and both needed their own migration to undo. The fragile rows all sit on **locked** sheets the route could never reach. **153** — the derive trigger erased imported grades: 3,476 entries hold a final grade with no component marks, and a maintenance `UPDATE` would have nulled them. **154** — normalisation deleted marks: 232 of 1,116 sheets have no maxes configured, so rebuilding score arrays emptied them, **3,908 marks across 513 entries**. The general guard is _derive only when something meaningful can be derived, and never let a computed null overwrite a stored value_ (`coalesce(new.col, old.col)` — an explicit value still wins, so imports write; pad arrays, never truncate). ⚠ **Before porting a rule into a trigger, query production for rows that violate its assumptions — first, not after.**

🔴 **APPLY 143 AND MOVE THE ACCOUNT BEFORE THE CODE DEPLOYS — the wrong order is a LOCKOUT, not an error.** A role that no longer resolves is read by this app as a **PARENT**. Migration 143 alone is safe in either order (it changes what the role MAY do, not who holds it); the deploy is the irreversible half. Already resolved for this change: Louilyn is on `admissions` and **zero accounts hold `p_file_officer`**, verified by direct query. ⚠ **The string SURVIVES in `audit_log.actor_role` on historical rows and must never be back-filled away** (append-only, Hard Rule #6) — `lib/audit/humanize.ts::RETIRED_ROLE_LABELS` is the one thing keeping those rows rendering "P-File Officer" instead of a raw identifier. **Any future role retirement adds a row there in the same commit.**

⚠ **GENERATED SQL NOW HAS A LINTER, BECAUSE REAL BUGS REACHED A FILE.** A row comment placed _after_ a `VALUES` row swallowed the separating comma (silently truncating the list); a `DO` block was emitted with repeated `begin/end` pairs instead of one (would not parse); and a `create temp table` grew a column while its `VALUES` rows kept the old arity — **SQL that cannot run, which every other check passed because the commas, quotes and parens were all balanced** (2026-09-15, the calendar level-scope file). `scripts/backfill/lint-generated-sql.ts` checks balanced transactions, one-`begin` DO blocks, the comma trap, quote/paren balance, and column-vs-value arity across every generated `.sql`. **Run it before handing any generated SQL to Mr Ace** — and each check was proven against a deliberately broken file, not just a clean pass.
