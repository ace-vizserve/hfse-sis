# HFSE SIS — Claude Instructions

A Student Information System for HFSE International School, Singapore. Modules — Markbook, Attendance, Evaluation, P-Files, Records, Admissions, SIS Admin — are surfaces of one student record, not sibling apps. The module switcher moves between them; `studentNumber` is the backbone.

## Stable rules — auto-loaded (every session)

**Everything inside `.claude/rules/` is read into context automatically, every session.** That is a Claude Code behaviour, not something a file can opt out of — a `load: on-demand` line in a file's frontmatter is descriptive only and does not stop it loading. So only four files live there, deliberately:

@.claude/rules/always-do-first.md
@.claude/rules/hard-rules.md

- `.claude/rules/design-system.md` — binding design pointer; too important to risk missing (it is small, and only points at the full docs).
- `.claude/rules/key-decisions.md` — the KD index, so a "KD #N" cite resolves with no extra read.

Do not edit any of the four without explicit user approval, and **do not add new files to `.claude/rules/`** — anything put there is paid for in every session. On-demand material goes in `docs/` (below).

## Session context

✅ **THE P-FILES OFFICER ROLE IS GONE, AND ADMISSIONS DOES THAT JOB NOW — 2026-09-10. `ROLES.length === 5`. Migration 143 is WRITTEN AND NOT YET APPLIED. Full account: KD #207.** Exactly one account held `p_file_officer`, and the job it named — chase a parent for a passport, approve what arrives, upload a replacement — is the job admissions already did on the applicant side. Two roles for one lifecycle meant every document rule was written twice and kept in step by hand. **`admissions` absorbed all eight `documents_*` capabilities, both sides of enrolment**, reaches `/p-files` and `/records`, and **may now place students in classes and withdraw them** (`ENROLMENT_PLACEMENT_WRITERS` and `STUDENT_RECORD_WRITERS` are the same four roles — this supersedes KD #180's `placement_forbidden` 403 and KD #51's exclusion). Nobody's rights shrank: `school_admin` and `superadmin` already held all eight.

🔴 **APPLY 143 AND MOVE THE ACCOUNT BEFORE THE CODE DEPLOYS — the wrong order is a LOCKOUT, not an error.** A role that no longer resolves is read by this app as a **PARENT**. Migration 143 alone is safe in either order (it changes what the role MAY do, not who holds it); the deploy is the irreversible half. Already resolved for this change: Louilyn is on `admissions` and **zero accounts hold `p_file_officer`**, verified by direct query. ⚠ **The string SURVIVES in `audit_log.actor_role` on historical rows and must never be back-filled away** (append-only, Hard Rule #6) — `lib/audit/humanize.ts::RETIRED_ROLE_LABELS` is the one thing keeping those rows rendering "P-File Officer" instead of a raw identifier. **Any future role retirement adds a row there in the same commit.**

✅ **AN ENROLLED STUDENT'S ADMISSION RECORD STAYS EDITABLE — KD #147's post-enrolment stage freeze is REMOVED (same day, independent change).** Mr Ace: _"regarding the prevention of updating admission record in admissions if student is already enrolled we should just enable that its all audit logged anyways"_. The rule froze every funnel stage once `applicationStatus === 'Enrolled'`, **for every role including superadmin** — module ownership, not permissions — so a typo in an enrolled child's record was uncorrectable by the people who own it. **What makes removal safe is the audit row the stage PATCH already writes on every field change, and nothing else.** `isAdmissionsStageFrozen`, `POST_ENROLMENT_EDITABLE_STAGES` and `STAGE_FINALIZED_STATUSES` are **deleted, not left dormant**; `__tests__/sis/enrolled-record-stays-editable.test.ts` asserts they stay gone. The prerequisite gate on the flip **to** Enrolled is a different rule and still fires. ⚠ **Three stage fields now have teeth:** `fatherEmail` and `guardianEmail` each gate two document slots and `Enrolled (Conditional)` gates one — clearing a gate **hides** a slot that may already hold an approved file (nothing is deleted; restoring the gate brings it back).

⚠ **A GREEN AUTH SUITE DOES NOT CERTIFY A ROLE CHANGE HERE.** `link-capability-consistency.test.ts` models only `role !== 'x'` inequality chains and is **blind to `ALLOWED_ROLES.includes(...)` and `requireRole([...])`** — roughly a third of the app's guards. **Four separate follow-up commits on this branch exist solely because of that blind spot**: four Records `ALLOWED_ROLES` guards, the P-Files drill and revisions guards, and a section-move link that rendered for a role which cannot open its destination. **Sweep role guards by hand.** ⚠ **`npx tsc --noEmit 2>&1 | grep -v '.next/dev/types'` CAN LIE** — a corrupt partially-written file in `.next/dev/types/` suppresses semantic checking program-wide, so filtering those lines turns "checked nothing" into "0 errors, clean". **If tsc comes back suspiciously empty, delete `.next/dev/types/` and re-run** (`--listFiles | wc -l` is the cheap positive control: ~3,900 here).
