# HFSE SIS — Claude Instructions

A Student Information System for HFSE International School, Singapore. Modules — Markbook, Attendance, Evaluation, P-Files, Records, Admissions, SIS Admin — are surfaces of one student record, not sibling apps. The module switcher moves between them; `studentNumber` is the backbone.

## Stable rules — auto-loaded (every session)

**Everything inside `.claude/rules/` is read into context automatically, every session.** That is a Claude Code behaviour, not something a file can opt out of — a `load: on-demand` line in a file's frontmatter is descriptive only and does not stop it loading. So only four files live there, deliberately:

@.claude/rules/always-do-first.md
@.claude/rules/hard-rules.md

- `.claude/rules/design-system.md` — binding design pointer; too important to risk missing (it is small, and only points at the full docs).
- `.claude/rules/key-decisions.md` — the KD index, so a "KD #N" cite resolves with no extra read.

Do not edit any of the four without explicit user approval, and **do not add new files to `.claude/rules/`** — anything put there is paid for in every session. On-demand material goes in `docs/` (below).

All four badge subscriptions moved from `postgres_changes` to `realtime.send()` in a trigger. **The swap was cheap for one reason: not a single handler ever read the event payload** — they all re-count against the server, so the event has only ever meant "something moved, go look again", which is exactly what a broadcast ping is. 🔴 **THE P-FILES AWAITING-VERIFICATION BADGE HAD BEEN DEAD SINCE 2026-05-19.** `audit_log` is not in the `supabase_realtime` publication and never was (query run against production) — a `postgres_changes` subscription on a table outside the publication is accepted by the client and silently never delivers. **State it precisely: the badge was never blank or wrong**, it is SSR-rendered so every page load was correct; what never fired is the `router.refresh()`. Already fixed, because a trigger does not need the publication. 🔴 **`lib/sidebar/badge-bus.ts` EXISTS FOR A REASON — DO NOT DELETE IT AS INDIRECTION.** `realtime-js` dedupes channels by topic but `removeChannel()` is **unrefcounted** and tears down by topic, and `@supabase/ssr`'s browser client is a **singleton**, so all hooks share one registry: without the bus, the first badge to unmount silently kills every other subscriber on that topic, and `NotificationBell` is in all eight staff layouts so that fires on every module-to-module navigation. The bus refcounts, serializes teardown (a re-subscribe during an un-awaited leave would otherwise cache a torn-down channel **forever**), and carries a per-attempt cancellation token. ⚠ **`supabase.from(X)` RETURNS A `PostgrestQueryBuilder`, WHICH HAS NO `.eq()`** — filter methods live on what `.select()` returns.
