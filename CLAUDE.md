# HFSE SIS — Claude Instructions

A Student Information System for HFSE International School, Singapore. Modules — Markbook, Attendance, Evaluation, P-Files, Records, Admissions, SIS Admin — are surfaces of one student record, not sibling apps. The module switcher moves between them; `studentNumber` is the backbone.

## Stable rules — auto-loaded (every session)

**Everything inside `.claude/rules/` is read into context automatically, every session.** That is a Claude Code behaviour, not something a file can opt out of — a `load: on-demand` line in a file's frontmatter is descriptive only and does not stop it loading. So only four files live there, deliberately:

@.claude/rules/always-do-first.md
@.claude/rules/hard-rules.md

- `.claude/rules/design-system.md` — binding design pointer; too important to risk missing (it is small, and only points at the full docs).
- `.claude/rules/key-decisions.md` — the KD index, so a "KD #N" cite resolves with no extra read.

Do not edit any of the four without explicit user approval, and **do not add new files to `.claude/rules/`** — anything put there is paid for in every session. On-demand material goes in `docs/` (below).

Full account: KD #218.** Miss Joann asked whether she has to untick something per term: S3 Filipino has an exam in some terms and not others, Global Perspectives had none in Term 3, _"those subjects have PT scores only, and the PT score effectively is the exam"_. 🔴 **The flag she was pointed at is the wrong one.** `subjects.is_examinable` means numeric-vs-LETTER grading (migration 049), has no AY dimension, and unticking it would have made Filipino letter-graded in every year at once. Mr Ace: _"our definition of examinable is wrong … its the grading sheet that needs it instead of the subject."_ 🔴 **And it was a live defect:** `(qa_ps ?? 0) * qa_weight` gives a missing component ZERO rather than handing its weight back, so a no-exam term graded Filipino out of 80 — full marks scored **87**, and Global Perspectives on performance tasks alone scored **72**. ⚠ **`lib/compute/quarterly.ts` is NOT modified and must not be** — with `qa_weight` at 0 the formula was already right, it was being fed the wrong weights. `grading_sheets` now carries its own weights (nullable = inherit), set for a whole term on **Subject setup** or for one class in **Edit totals & slots** (the per-section case Mr Ace asked for: _"currently its per level and there might be cases where its per section"_). ⚠ **Redistribution is integer percentage points with the tie broken deliberately** — the first version divided fractions and `0.3/0.8` is `0.37499999…`, so a real 37.5 tie was decided by representation error; Filipino lands on **37/63**. ✅ **Measured first and the live damage was 2 students, AY2025 clean across 348 sheets** (`scripts/audit-missing-component-weight.ts`) — **no `subject_configs` row anywhere has ever carried a zero weight**, so this is a **pre-import fix, not a cleanup**, and a prerequisite for the T3 grading import, which would otherwise overwrite the year's weights a third time. ⚠ **Slots were already per-term and needed nothing** (`ww_totals`/`pt_totals`/`qa_total` since migration 001 — Math already holds nine distinct T1 exam totals); only the weights were stuck at year level. 🔴 **DEPLOY ORDERING: 159 before this code**, same trap as 138. ⏳ **Not browser-verified yet** — the canonical check is an S3 Filipino T3 sheet with Exam unticked showing 100, not 87.
