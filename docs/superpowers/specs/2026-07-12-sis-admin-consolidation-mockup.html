HFSE SIS · SIS Admin makeover · v2

Admin that speaks HFSE's language

Two changes from what exists today. One: every admin screen is rebuilt around the real thing it feeds — the grading sheet teachers fill in, the attendance register, the printed report card, the parent application form — with a live preview of that artifact on the page, so Chandana and Joann configure by looking at the result, not at a matrix of fields. Two: the presentation moves to the modern shadcn dashboard idiom used by current production SaaS — clean sans type, quiet cards, real tables, pill statuses — no bespoke ceremony. Six surfaces, one sidebar, HFSE defaults pre-filled everywhere.

Screen 1 · Grading setup — /sis/structure

The page IS the grading sheet. Pick a level, and each subject row shows exactly the columns teachers will get — WW slots in blue, PT in green, QA in amber — with HFSE's standard weights applied by default (Primary 40/40/20 · Secondary 30/50/20). Changing slots updates the preview live; unlocked sheets sync on save. No more abstract "subject config matrix."

What gets simpler, function-wise

Configure by preview, not by field

Grading sheet columns, the calendar month, the report-card header, and the application form's level list are rendered ON the admin pages. You see what teachers/parents will see while you edit it — the single biggest de-jargoning move.

HFSE defaults do the typing

Primary 40/40/20 and Secondary 30/50/20 are one-click "standards" (already in the DB per KD #4/#153) — a subject is "Standard" or "Custom", not eleven number inputs. New sections suggest the official virtue names + schedule (KD #144). New years copy Year Defaults automatically.

Common actions become one button

"Add a closure", "Generate class index", "Offer for AY2027", "Upload signature" — each named pain point gets a first-class button on the page where you notice the problem, instead of a trip through a settings matrix.

Modern shadcn idiom, no bespoke ceremony

Built from the shadcn primitives already installed (Card, Tabs, Table, Badge, Button) in the dashboard-01 layout language: sans type, quiet borders, pill statuses, one primary button per screen. All colors stay on existing Aurora Vault tokens (Hard Rule #7) — this is a restyle of presentation, not a new palette.

Preview only — links inert, values illustrative. The 13→6 route consolidation already built (six surfaces, cut tabs, redirects, role gating) is the skeleton this hangs on; what changes now is every page's CONTENT: artifact previews, HFSE defaults, and the modern presentation shown here. Approve this and implementation restyles the real pages to match, screen by screen.
