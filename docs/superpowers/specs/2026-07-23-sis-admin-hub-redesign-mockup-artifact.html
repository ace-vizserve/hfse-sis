Open questions for you: (1) Is this too dense for a page "admins live in" every day, or does more context here actually reduce clicking around? (2) Module overview — real numbers, or should each card just deep-link into that module's own dashboard without duplicating a metric? (3) Recent activity — governance/config changes only (as shown), or does it need grade-change and enrollment events too? (4) Anything here that should just not exist.

On the readiness step detail: a "Summary" button on the year band opens it as a real Popover (the same primitive already used elsewhere for facet filters / inline editors) anchored right under the button — shown open here for review, but by default the hub stays exactly as compact as it is today; the detail only exists when someone actually clicks for it, and closes on click-away or Escape. Costs zero permanent page height, which was the whole point of moving it out of an always-visible inline panel. Real data note: the numbers/labels/grouping ("Core setup" / "Grading & staffing" / "Branding & admissions" / "Optional") are pulled directly from the existing getAyReadiness() engine and the full checklist page's own clustering — nothing invented, this is genuinely what the system already tracks per step.
