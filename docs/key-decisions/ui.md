### KD #24

> **Reversed (2026-06-15) — TanStack Query v5 is now the client data layer.** The original rule ("client mutations = raw `fetch` + `toast.error`; no React Query") was deliberately dropped: as the codebase grew, the hand-rolled `useEffect`-fetch reads had no abort-on-unmount/race handling (the "unstable fetching" symptom) and every mutation re-implemented an `isSubmitting` flag. All **80** client components that called `fetch()` were migrated to TanStack Query.

**The standard:** all client→API calls route through **`lib/query/fetcher.ts::apiFetch`** (the single chokepoint — throws a typed `ApiError` with `.status`/`.body`/`.message` already resolved to the response body's `error` field; `jsonInit(method, payload)` builds JSON mutations). `useQuery` for reads, `useMutation` for writes. Provider: `components/providers/query-provider.tsx` mounted once in `app/layout.tsx` — query defaults `{ staleTime: 60s, retry: 2, refetchOnWindowFocus: false }`, **mutations `{ retry: 0 }`** (never auto-replay a non-idempotent POST/PATCH/DELETE). Typed query-key factory in `lib/query/keys.ts`. **`toast` (KD #21) is still the feedback mechanism** — it now fires from `onError`/`onSuccess`.

**Model A (RSC-first, binding):** the app loads most data in server components, so `useMutation.onSuccess` **still calls `router.refresh()`** (and relies on server `revalidateTag`, KD #80) — we do **not** move RSC-loaded data into the client cache. Reads that were lazy client `useEffect` fetches (drill sheets, lookups, palette, history) become `useQuery`.

**Drill-seed rule (the seed is a placeholder, not authoritative — 2026-06-15 fix):** drill sheets are seeded from a server-prefetched row array for instant paint, but the per-`(target, segment)` narrowing happens **server-side in the drill route** (KD #82). So a seed is a **`placeholderData`** (paint instantly, but the query **always fetches** the narrowed rows and replaces it) — NOT `initialData`. Using `initialData` + `initialDataUpdatedAt: Date.now()` marks the broad seed _fresh_ under the 60s `staleTime`, which **skips the narrowing fetch → every drill shows the same full unfiltered set** (the bug this rule prevents). The lone exception is the markbook drill, whose seed is **client-narrowed via `applyTargetFilterClient` to exactly equal the fetch** — only such a seed may use `initialData` (skip the fetch). Reproduction + regression test: `__tests__/query/drill-seed.test.tsx`. Non-drill reads (palette/search/history/lookup) gate on `enabled` and have no seed.

**Error preservation (hard rule of the migration):** routes return specific codes (422 `publish_blocked`/`comments_incomplete`, 409 `grading_lock_date_passed`/`pending_change_requests`, `body.warning`, …). `onError` reads `ApiError.message`/`.body`/`.status` to surface the **exact** route-specific message/dialog — never a generic toast.

**Optimistic tiers:** (1) inline toggle / queue-row actions whose value is local list state → optimistic `onMutate` snapshot-from-closure + rollback in `onError` (reference: `components/admissions/document-validation/validation-queue.tsx` — snapshot from the closure, NOT from inside a `setState` updater); (2) dialog→submit→close→refresh → pending-only (`isPending`); (3) **autosave grids** (`score-entry-grid`, `totals-editor`, `wide-grid`, `daily-entry`) keep their existing **local-state** optimism (KD #20 unchanged) — only the network call routes through `useMutation`. References: `components/grading/totals-editor.tsx` (Tier-2 mutation), `components/admissions/drills/admissions-drill-sheet.tsx` (read). Component tests live under `__tests__/` (`.test.tsx`, jsdom + `@testing-library/react`; helpers in `__tests__/_utils/`).

### KD #161

Column **display names live in `meta.label`; `header` is presentation only** (2026-07-29; no migration). The shared shell's "Columns" visibility menu and the CSV export both derived a column's name as `typeof header === 'string' ? header : column.id`. Because ~every consumer writes `header: ({ column }) => (<SortableHeader column={column}>Section</SortableHeader>)` — a **function** — that fell through to the raw id on **140 columns across 33 files**, surfacing developer identifiers (`levelLabel`, `fcaName`, `daysUntilExpiry`, and generated ids like `writeups_<uuid>`) in a menu school admins read, and as the literal header row of every downloaded CSV.

- **Resolver** `components/ui/data-table/column-label.ts` — `resolveColumnLabel(column)` (live `Column`, for the menu) + `resolveColumnDefLabel(col)` (raw `ColumnDef`, for the export sheet, which never builds a table). Two exports over one private core deliberately: `Column` and `ColumnDef` overlap structurally, so a single permissive signature would silently accept the wrong shape. Fallback chain **`meta.label` → a plain NON-EMPTY string `header` → `humanizeFieldName(id)`**. The non-empty guard matters — several action columns use `header: ''`, which is a string and previously rendered a blank, unlabelled checkbox row.
- **`ColumnMeta` augmentation** (bottom of `components/ui/data-table/types.ts`) types `label` + the pre-existing `excludeFromExport`, replacing an inline cast. It is **global once that module is in the program** — a future `meta: { somethingElse }` anywhere becomes a compile error until declared here. Deliberate.
- **Auto-humanize is a safety net, not the plan.** Measured: 100 of the 140 columns humanize to text that differs from their header, ~40 into different WORDS (`owner` → "Owner" but its header reads "Level"; `sectionName` → "Section Name" vs header "Class"; `iso` → "Iso" vs "Date"). Shipping the fallback alone would have replaced a raw id with a confidently-wrong label. Hence explicit labels on all 140.
- **Labels normally equal the header, and deliberately exceed it twice:** glyph headers expand (`#` → "Index number", `%` → "Attendance %" / "Documents complete %" — the latter is a _document_ completeness column, not attendance), and the two dynamic-id columns take the fuller name (`writeups_${t.id}` → `t.label` "Term 2" not the grid's "T2"; `slot:${h.key}` → the full `h.label`, not the grid's abbreviation).
- **`enableHiding: false` does NOT exempt a column.** `isExportableColumn` gates only on `NON_DATA_COLUMN_IDS` + `excludeFromExport` — so a non-hidable identifier column is absent from the menu but still ships its label as a CSV header. `open` (the audit logs' row-action link menu) was added to `NON_DATA_COLUMN_IDS` alongside `select`/`actions`/`action`.
- **CSV headers changed** (`daysSinceUpdate` → "Days since update"). Accepted trade-off — anyone with a spreadsheet keyed on the old raw text re-maps once. The export sheet's column-search box filters on the label too.
- **No id changed**, so filters, facets, sorting, status tabs, and URL state are untouched — labels are display-only. Column visibility is plain `useState`, never persisted, which is also why making the 6 blank action columns `enableHiding: false` strands no saved state.
- **Drift guard** `__tests__/ui/data-table-column-label-coverage.test.ts` uses the TypeScript compiler API (not regex — a regex scan crosses object boundaries in `cohort-table.tsx`'s five builders) and **auto-discovers consumers**, so new tables are covered with no maintenance. It asserts: every function-header column reachable by either surface declares a label; a literal label matches its header (glyphs and an `INTENTIONAL_LABEL_DIVERGENCE` map excepted); no hidable blank-header column. Proven to bite by deliberately removing a label and renaming a header — two distinct, actionable failures.
- **Not duplicates** (checked, both by design): `cohort-table.tsx` repeats "Student"/"Level" once per its five independent builders; `my-requests-table.tsx` repeats "Filed"/"Reason"/"Status" between `excludeFromExport` on-screen columns and their `csv.extraColumns` equivalents — the two never appear in the same surface.

Cross-ref KD #84 (the shell), KD #15 (TanStack canonical). Out of scope: `components/dashboard/drill-down-sheet.tsx`, a separate bespoke implementation whose own visibility menus render `DrillDownColumnOption.label` from `DRILL_COLUMN_LABELS`.

- **Presets export raw DB columns ONLY — they are NOT a superset of the screen.** An on-screen column sourced elsewhere is absent. The sheet's copy must never claim otherwise (it briefly did); per-preset `description` carries the real distinction.
- **THE SUBTLE PART — object-valued columns are dropped entirely** (user ruling: neither `[object Object]` nor a JSON blob helps in a spreadsheet), **and the probe must scan EVERY value, not sample the first.** `residenceHistory` is **heterogeneously typed in production** — the parent portal and seeder write a **JSON string** (`lib/sis/seeder/populated.ts`), the SIS edit route writes a real **array**; `lib/sis/cohorts.ts::isResidencePopulated` already branches on all three shapes. A first-non-null sample made the result **sort-dependent**: the same table with the same rows either kept the column (emitting JSON blobs) or silently dropped it, depending on which row sorted first. Rule: a column is object-valued — and dropped — if **any** non-null value is an object. Applied to both the on-screen path (`export-payload.ts`) and the raw path (`export-sheet.tsx`), with order-independence pinned in tests. Note Dates and Arrays are `typeof 'object'` too; an exhaustive sweep of all 16 tables confirmed no on-screen column returns either.
- **`csv.extraColumns` semantics changed** with the picker's deletion: `defaultChecked: true` → **always** exported; omitted → **never** exported (previously "opt-in via the picker"). Adding an extra without `defaultChecked` now silently ships an unreachable field. Only surviving consumer is `my-requests-table` (all 6 set it). The 8 extras on `student-data-table` were **deleted** — all were `_enrolment_status` columns superseded by the "+ pipeline" preset.
- **New shared module** `components/ui/data-table/export-payload.ts` (pure): `ExportField`, `isExportableColumn`, `resolveColumnId`, `buildScreenFields(columns, visibleColumnIds, extraColumns, rows)`, `fieldsToCsvColumns`. Both surfaces build from it, so button and sheet cannot diverge. `export-sheet.tsx` 1109 → ~212 lines; **`@dnd-kit/{core,sortable,utilities}` uninstalled** (its only consumer); `getFacetOptions` deleted from `filter-rows.ts` (orphaned). `NON_DATA_COLUMN_IDS` gained `open` (the audit logs' row-action menu) alongside `select`/`actions`/`action`.

Both correctness-neutral. ### KD #168

**Document Completeness — colour encodes the ACTION, words carry the CAUSE** (2026-07-30; no migration). `components/shared/document-completeness-table.tsx` (both consumers: `/p-files` and `/admissions`) gave 13 columns to a per-slot status-dot matrix that could not be decoded, in principle:

- **Seven statuses were painted in five colours.** `expired`/`rejected` both `bg-destructive`; `missing`/`na` both `bg-muted` (one bordered). Two pairs were indistinguishable **even to someone who hovered every dot** — so no legend could have rescued it. This is the §10.5 rule ("no two distinct states share a swatch") being broken, not a styling complaint.
- The 13 columns also took the table's width first, so student names wrapped onto three lines, every row was a different height, and the `%` badge sat past a horizontal scroll **behind the dots it summarised**.

**The fix reuses an in-house pattern rather than inventing one.** `components/shared/document-completeness-strip.tsx` collapses the 13 columns into one 112px strip — one segment per slot, in `DOCUMENT_SLOTS` order, **fixed across rows so scanning down a position still works the way the matrix allowed** — with a Popover naming every slot in full plus its expiry date. Same shape as `components/sis/pipeline-strip.tsx`, which solved exactly this for the 9 admissions stages (KD #152). Beside it an **Outstanding** column names the exceptions in words (3 chips, then `+N`); on a chase surface the exceptions ARE the job, so they get the widest column.

**The load-bearing idea, in `components/shared/document-status-visuals.ts`:** split `DocumentAction` (what the officer must DO — five: `clear` / `check` / `waiting` / `reupload` / `collect`, plus `na`) from `DocumentStatus` (what HAPPENED — the existing seven). **Colour keys off the action; the chip's word + icon key off the status.** `expired` and `rejected` share a fill _on purpose_ — either way the parent must send it again — and that merge is what lets the legend hold **one meaning per swatch**. `missing`/`na` no longer collide: not-collected is chase work, not-applicable is out of scope. Every chip renders icon **and** tint, so status is never colour alone.

- **The ratio replaced the percentage.** `9/13` in tabular mono, sorting identically — the officer collects documents, not percentages. `na` slots are excluded from **both halves**, matching `StudentCompleteness.total`, so a student with no father on file doesn't read as incomplete.

### KD #186

**Every write reports itself through one lifecycle — `useWriteAction`** (2026-08-14 → 2026-08-17; no migration). An audit of all 80 client components that perform a write found the three feedback signals were not equally covered: `toast.error` appeared in 78 of 78 applicable files and `toast.success` in 76, but the **in-flight phase appeared in exactly one**. So the gap was never "nobody toasts". It was that a write reported success at the wrong moment.

**The defect this fixes.** A mutation resolves, the code toasts "Saved", closes the dialog and re-enables the button — while `router.refresh()` is still in flight. The list underneath is still the old list. The user is told the work is done while it visibly is not. That gap is the "sluggish and unfinished" complaint, and it is a correctness problem, not polish.

**The contract.** `lib/hooks/use-write-action.ts` gives every write one lifecycle: pending toast (suppressed below `PENDING_DELAY_MS` = 250ms so a fast write never flashes) → the work → `onResolved` (the surface reacts: close the dialog, reset the form) → **awaited** `router.refresh()` → terminal toast. `run` **never rejects** — it resolves the parsed body, or `undefined` on failure — which removed the `.catch(() => {})` incantation from every call site.

- **It wraps the promise, not `useMutation`.** Deliberate, and load-bearing: replacing `useMutation` would mean absorbing every branch its call sites rely on — `onMutate` optimistic snapshots, `onError` rollbacks, error handlers that open a dialog. Those all stay put. Only the toast and refresh lines move. Both optimistic validation queues (`p-files`, `admissions`) keep their snapshot-and-rollback untouched, which is the proof the choice was right.
- **`error` may return `null`** — "the surface answers this itself" (a dialog explaining a 409). **`success` may return `null` too**, added when the sweep hit the case: a write can SUCCEED and still owe the user a _warning_. An upload that landed but merged the PDFs, an import that finished with sheet-level issues, a change request whose approvers couldn't be emailed. The alternatives were a green toast carrying warning text, or two toasts for one action.
- **`refresh` takes a predicate.** Used where only the response knows: a dry-run import writes nothing; an all-failed batch changed nothing; `new-section-button` navigates away on one branch.
- **`pending: false`** means the surface shows the change itself — the two optimistic queues, the house tile, the STP select, the pre-course date cell, the bulk-publish dialog (which shows a real "3 of 12" count), and `school-config-form` (inline "Saved" tick). Every one is allowlisted with a reason.
- **`Button` gained `loading` / `loadingText`** (§9 / 09a:210 — reusable treatment belongs in the variant). This collapsed four hand-rolled in-flight idioms across ~107 sites onto one. ⚠ **`loadingText` changes a button's accessible name in flight** — "Save" becomes "Saving…" — so `getByRole('button', { name: /^save$/i })` stops matching it.

**Guard:** `__tests__/ui/write-feedback-coverage.test.ts`, source-scanning, ratcheted through the sweep via `CONVERTED_ROOTS` and now covering every root. Five rules; the two that matter most catch silent damage — no `toast.success` beside the helper (double-toasting) and no bare `router.refresh()` beside it (double-_refreshing_, which is invisible and worse: `markbook/grading/[id]/page.tsx:156` performs a DB write on every render). Every exemption carries `{ decided, why }`, stale entries fail, and positive assertions check the exempt files still do the thing that exempts them — so the allowlist cannot become a lie by editing the allowlist alone.

**Three things the guard itself taught, each a rule now:**

1. **The write-detector cannot be `jsonInit(` alone.** That missed `p-files/upload-dialog.tsx`, which posts multipart FormData and therefore _cannot_ use `jsonInit` — the app's slowest write, and the one most needing a pending toast, was not classified as a write at all. It now also matches a hand-rolled `method: 'POST'|'PATCH'|'PUT'|'DELETE'`.
2. **A source scan must read code, not prose.** Its first run flagged three files whose _comments_ explain why they no longer call `router.refresh()`. It now strips comments, string-aware, so a `https://` is not mistaken for a line comment.
3. **`useDebouncedRefresh(() => router.refresh())` is not a second refresh.** A file may hold both kinds of write — `attendance/wide-grid.tsx` does — so the sweep reads **statements, not files**: its per-cell autosave stays exempt while its `metaMutation` converted.

**Four real defects found by doing the conversion, not by looking for them:**

- **Two parents double-refreshed their children.** `calendar-admin-client.tsx` passed `onSaved={() => router.refresh()}` _and_ an `onCreated` that refreshed again, while each child needed one too. Rule adopted: **the component that owns the write owns the wait.** A `onSaved`/`onCreated`/`onDone` prop whose whole body was `router.refresh()` is now deleted, not kept — the same for `late-enrollee-prompt` (two parents), `new-subject-form`, and `day-action-sheet`.
- **`classroom-settings-form.tsx` never refreshed at all** — it saved the note, updated its own baseline, toasted, and left every server-rendered copy showing the old text.
- **`bulk-publish-dialog.tsx` reported total failure as success:** `toast.success("Published 0 sections · 12 failed")`. Nothing-published-and-something-broke is now an error; partial outcomes are a warning.
- **Both Class B late-enrollee bugs are fixed by construction.** `edit-stage-dialog` and `enrolment-edit-sheet` each returned early on the mid-term branch, relying on a later second refresh; the helper's unconditional awaited refresh removes the branch entirely.

**Also:** `BulkActionFooter` now awaits `onTrigger`, holds per-action pending state and disables its siblings — honouring a `void | Promise<void>` contract its type had always declared. All three consumers today are synchronous, so this is a double-click guard and cover for the first async one, **not** a fix for anything currently broken.

⚠ **Expect it to feel slower on day one.** Holding the toast until the refresh commits honestly reports a wait that was previously hidden behind a closed dialog. That is the point. It is affordable because the attendance batching landed first (90 → 6 round-trips for a class of 30).
