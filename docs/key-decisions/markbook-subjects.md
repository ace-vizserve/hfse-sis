### KD #100

Non-examinable `annual_letter_grade` (migration 053). Registrar-entered year-end grade for non-examinable subjects (Music, Arts, PE, HE, CL, CA, PEH, PMPD). Stored as `grade_entries.annual_letter_grade text NULL` on the T4 row. **Controlled value set** (confirmed HFSE workflow): `['Passed', 'UG', 'E', 'NA']` — exported as `ANNUAL_LETTER_VALUES` from `lib/compute/letter-grade.ts`. "Passed" is the routine year-end entry; UG/E/NA are override codes. First-time entry (null → value) saves immediately; changing an existing value requires a correction note. Hard Rule #5 does NOT apply — this is registrar metadata, not a locked score. Route: `PATCH /api/grading-sheets/[id]/entries/[entryId]/annual-letter` (registrar/school_admin/superadmin) validates against `ANNUAL_LETTER_VALUES`. UI: `<AnnualLetterInput>` inline popover in the report card T4 Final column. Publish-readiness checks that all T4 non-examinable rows have `annual_letter_grade` set or `is_na=true` (KD #28). **Distinct from `grade_entries.letter_grade`** (per-term quarterly override, KD #104).

**Update (2026-06-09):** the original text listed `<AnnualLetterInput>` as surfacing "in the Masterfile grid and report card T4 Final column." The Masterfile grid (`components/markbook/masterfile-grid.tsx`) was deleted by KD #134; `<AnnualLetterInput>` now appears **only** in `components/report-card/report-card-document.tsx` (the T4 Final column). The PATCH route and value set are unchanged.

### KD #104

Non-examinable subjects use the same WW/PT/QA score entry as examinable subjects (migration 055). The Quarterly cell displays a derived letter via `lib/compute/letter-grade.ts::numericToLetter`: A (90–100), B (85–89), C (80–84), IP (≤79). Manual override codes **UG and E** are stored in `grade_entries.letter_grade` and take precedence over the derived letter (INC/CO were removed — not in HFSE's confirmed legend). NA is the existing `is_na` checkbox. A/B/C/IP/NA are never written by the score-entry flow — they are derived at render time via `resolveNonExaminableLetter({ isNa, letterOverride, quarterly })`. Migration 055 cleared all legacy `letter_grade` values for non-examinable rows (teachers must re-enter via the score grid). `<ScoreEntryGrid letterDisplay={true}>` is the unified entry surface; the legacy `<LetterGradeGrid>` was deleted. T4 `annual_letter_grade` (KD #100) is unchanged — registrar-entered freeform, takes precedence over the derived letter on the report card Final column. `<TotalsEditor>` is now shown for all subjects (not gated on `isExaminable`). The entries PATCH route (previously short-circuiting non-examinable) now runs the full WW/PT/QA + `computeQuarterly` path for both subject types; `letter_grade` writes validate against the override allowlist only.

**Update (2026-06-03) — derived-letter display wired + per-term override entry now ships.** The `letterDisplay` prop existed but was never consumed (the Quarterly cell rendered the raw number); `QuarterlyPill` now renders the derived letter (A/B mint, C neutral, IP amber, NA/UG/E neutral) when `letterDisplay` is set. Per-term UG/E entry, previously not enterable from any UI, now ships: the N/A checkbox is replaced by a unified **"Override" dropdown** (—, N/A, UG, E) for non-examinable subjects in `<ScoreEntryGrid>` — `—` clears both columns (derived letter shows), N/A → `is_na`, UG/E → `letter_grade`; the two-column N/A↔UG/E jump is blocked on locked sheets ("clear to — first" toast). The unlocked entries-PATCH path now actually writes `letter_grade` behind an `OVERRIDE_LETTERS = ['UG','E']` allowlist (`isOverrideLetter` guard in `lib/compute/letter-grade.ts`; rejects A/B/C/IP and any `letter_grade` on an examinable subject), `approvedValueToPatchBody` gained the missing `letter_grade` case, and the locked-sheet change-request input is a constrained UG/E `<Select>` (creation route rejects non-UG/E).
